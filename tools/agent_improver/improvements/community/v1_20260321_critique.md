### Issues

**[HIGH] Reddit section has no template**
- Problem: The Reddit section under community.md lists 4 bullet points ("be upfront you're the developer", "Reddit rewards: transparency...") but no actual template structure, while the longform.md Reddit section has a full template. A user using /community to write a Reddit milestone post gets no structural guidance.
- Impact: Reddit output will be inconsistent and may not follow community norms.
- Fix: Add a community-specific Reddit template focused on engagement posts (milestone announcements, AMAs, dev check-ins, patch updates) distinct from the editorial posts in longform.md.

**[HIGH] Discord templates wrapped in markdown code blocks**
- Problem: All Discord templates are inside ` ```markdown ``` ` code blocks. This means Claude will output the entire Discord message as a code block in its response, forcing the user to read and copy from inside a code block every time.
- Impact: Every output requires an extra copy-paste step and the markdown formatting isn't rendered for the user to preview.
- Fix: Remove outer code block wrappers. The Discord templates should be shown as actual markdown, not wrapped.

**[MEDIUM] No type-selection guide at the top**
- Problem: The skill identifies 5 content types but gives no guidance on which to use when. "Write something about our new carnival area" — is that a general announcement or a community event?
- Impact: User must guess which type fits their request, or Claude picks sub-optimally.
- Fix: Add a type selector at the top: "If the request involves a **date/time/structured event** → Community Event. If it's **a code fix or improvement** → Patch Notes. If it's **a question/concern from the community** → Feedback Response. Otherwise → General Announcement."

**[MEDIUM] Patch notes greeting is hardcoded**
- Problem: "Hey carnival-goers! 👻" is embedded in the patch notes template as a constant. This is charming for regular updates but wrong for a critical hotfix or emergency patch.
- Impact: A patch that fixes a game-breaking crash gets a cheerful greeting, which can feel tone-deaf.
- Fix: Note that the greeting should match the patch tone: cheerful for regular updates, more direct for critical fixes.

**[MEDIUM] Community event timezone handling is optional when it should be required**
- Problem: "include multiple time zones if relevant" — for a global VR gaming community, timezones are almost always relevant.
- Impact: EU and APAC players miss events because the post only shows ET/PT.
- Fix: Make timezone inclusion required: "Always include at minimum ET, CET, and AEDT."

**[LOW] Emoji guide is one-directional (only lists emojis to use)**
- Problem: The emoji guide tells you WHAT emojis to use but not how many. The voice reminders section says "2-5 per post, not per sentence" but this is at the bottom.
- Impact: Minor risk of emoji overuse in some outputs.
- Fix: Move the "2-5 per post" guidance next to the emoji guide where it's needed.

### What's Working Well
- Opening role framing ("you know this community well — they're VR gamers, horror fans...") is the best of all skills — it immediately grounds the persona
- "Personality > polish in community spaces" is exactly right and prevents corporate drift
- Community feedback response principles are thoughtful and specific (acknowledge first, be honest about timeline, never dismiss)
- "When in doubt, be more human and less brand" is great guidance
- Emoji guide is contextually specific to INWIGO (carnival/Halloween set)

### Issues

**[HIGH] Content calendar prompt under-directs on specificity**
- Problem: Section 4 says "Fill in ALL {weeks} weeks" and "Specific topics are better than generic ones (e.g., 'Behind the scenes: how we made the funhouse mirrors' vs 'Dev content')" — but the table template only shows a header row and column names. Claude frequently interprets "fill in ALL weeks" by producing generic rows.
- Impact: The most actionable deliverable gets generic content ("TikTok post — week 3") instead of specific, pre-thought topics.
- Fix: Add explicit directive: "Minimum 4 rows per week with REAL topic names. Draw directly from the creative angles defined in Section 2. If you need to abbreviate, use a pattern note for weeks 4+ rather than generic row labels."

**[HIGH] No --dry-run flag**
- Problem: Same gap as content_batch_agent.py — no way to test output without saving a file.
- Impact: Accumulates campaign files during testing; no preview mode.
- Fix: Add `--dry-run` and `--output-dir` flags consistent with content_batch_agent.py's interface.

**[MEDIUM] Filename doesn't include timeline**
- Problem: Output filename is `{timestamp}_{type}-{weeks}wk.md` — e.g., `20260321_1400_launch-6wk.md`. Running a launch campaign twice with different timelines produces identically-named files (disambiguated only by timestamp).
- Impact: Hard to distinguish campaign files at a glance — especially when comparing plans.
- Fix: Include timeline in filename: `{timestamp}_{type}_{timeline_slug}_{weeks}wk.md`. Example: `20260321_launch_Q2-2026_6wk.md`.

**[MEDIUM] No --name parameter**
- Problem: There's no way to give the output file a meaningful custom name. A solo marketer testing two strategic variants of the same campaign type gets two files that are hard to tell apart.
- Impact: File management becomes confusing with multiple campaign variants.
- Fix: Add `--name "The Carnival Opens"` optional parameter that replaces the auto-generated name in both the filename and the document title.

**[MEDIUM] Missing context handling is silent**
- Problem: `campaign_architect.py`'s `load_context()` only prints a warning and continues. `content_batch_agent.py` counts placeholders and warns more aggressively. The campaign architect will silently produce a plan with `[context/game_facts.md not found]` embedded if files are missing.
- Impact: A generated campaign plan with missing context looks plausible but is full of gaps.
- Fix: Align with content_batch_agent.py's approach — count and surface missing context more prominently, with option to abort.

**[LOW] KPIs table doesn't prompt for baseline estimates**
- Problem: `| Baseline | Week {weeks//2} Target |` — Claude will leave the baseline column empty or put "TBD" without guidance, making the KPI table essentially non-functional.
- Impact: KPI section looks complete but isn't actionable.
- Fix: Add instruction: "If baseline is unknown, estimate a realistic range for near-launch indie VR game (Discord: 200-500, wishlists: 500-2,000) and note it's an estimate."

**[LOW] Campaign type validation is a help string only**
- Problem: Valid `--type` values are described in the help text only (`launch, pre-launch, halloween-event...`), not validated in code. Typos like `--type launc` are silently accepted.
- Impact: Minor — produces a valid-looking file with the wrong campaign type label.
- Fix: Add explicit choices list to argparse or normalize input to closest valid type.

### What's Working Well
- System prompt is the best in the project: "practical, opinionated", "no generic advice", "every recommendation a solo marketer can actually execute" — this sets a genuinely high bar
- max_tokens=10,000 is appropriate for a comprehensive campaign plan (most agents under-allocate)
- weeks validation (1-24) is good defensive programming
- The `campaign_name = f"{args.type}-{args.weeks}wk"` structure keeps filenames clean even if improvable
- Section 10 (Solo Marketer Priority Stack) with explicit "skip" list is unique and immediately useful
- The metadata YAML header makes output files machine-readable and trackable

### Issues

**[HIGH] No format detection fallback**
- Problem: "Identify the format from the request" gives no fallback for ambiguous requests like "write something about our launch" without a format keyword.
- Impact: Claude picks a format arbitrarily; user may get a press release when they wanted a blog post.
- Fix: Add fallback instructions — state what you're producing and why, or provide a one-line prompt asking for format confirmation when ambiguous.

**[HIGH] audience_personas.md is loaded but never used**
- Problem: All three context files are loaded including `audience_personas.md`, but none of the output templates reference audience targeting. A Steam page, blog post, and Reddit post each serve different audiences with different contexts.
- Impact: Content is calibrated to brand voice but not to the specific reader.
- Fix: Each format section should note which persona it primarily targets and how that shapes the content (e.g., Steam page → Alex (VR enthusiast) + Morgan (horror/co-op gamer); Reddit → Morgan + community members; blog → Jordan (indie supporter)).

**[MEDIUM] Blog post SEO guidance is thin**
- Problem: "SEO-aware (include INWIGO + key topic term)" is the entirety of SEO guidance.
- Impact: Blog posts may be poorly optimized or chase wrong keywords.
- Fix: Add brief SEO strategy note: prioritize branded + VR + genre keywords ("INWIGO VR horror game", "co-op VR survival game"); secondary: comp-adjacent terms ("games like Lethal Company VR").

**[MEDIUM] Press release lacks embargo/pitch guidance**
- Problem: The template shows `FOR IMMEDIATE RELEASE [OR: EMBARGOED UNTIL: DATE]` with no guidance on when to use embargoes, what they achieve, or how to decide.
- Impact: Marketer may not know when/why to use an embargo.
- Fix: Add a 2-line note: "Use embargo (typically 48-72 hours) when you want coordinated coverage across multiple outlets on the same day. Use 'For Immediate Release' for reactive news or announcements already public."

**[MEDIUM] No blog word count guidance**
- Problem: Blog post structure is detailed but gives no length target. "Introduction + 3-5 body sections + conclusion" could be 400 words or 4,000.
- Impact: Outputs may be wildly over/under length for the intended use.
- Fix: Add "Target length: 800-1,200 words for dev diaries; 1,500-2,000 for feature posts. Include estimated read time."

**[LOW] Reddit template lives in two places**
- Problem: Reddit post template exists in both `longform.md` and `community.md`, with slightly different guidance. These will drift apart over time.
- Impact: Inconsistent Reddit advice depending on which skill is used.
- Fix: Note which skill owns Reddit (longform.md for editorial posts; community.md for community engagement posts) and differentiate the use cases.
